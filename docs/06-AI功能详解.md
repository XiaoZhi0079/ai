# AI 功能详细文档

## 1. 多模型对话系统

### 1.1 支持的平台与模型

| 平台 | Base URL | 模型列表 |
|------|----------|---------|
| DashScope（阿里云） | `https://dashscope.aliyuncs.com/compatible-mode` | qwen3.5-flash, qwen3.5-plus, qwen-plus-latest, qwen3.5-122b-a10b, qwen3-coder-next, kimi-k2.5, glm-5 |
| ModelScope | `https://modelscope.cn/openapi` | GLM-4.8, gpt-4, gpt-5 |
| iFlow | `https://apis.iflow.cn` | qwen4-coder, qwen4-max-preview, deepseek-v3.5 |

### 1.2 模型加载策略

系统支持两种模型加载策略：

#### 策略一：懒加载（当前主要使用）
- 通过 `ChatClientFactory.getClient(modelName)` 实现
- 使用 `ConcurrentHashMap` 缓存已创建的 `ChatClient`
- 首次请求时才创建模型实例
- 优点：启动快、内存占用低

#### 策略二：预加载（保留）
- 通过 `ChatModelConfig.ChatClientconfig()` Bean 实现
- 启动时创建所有模型的 `ChatClient` 实例
- 存储为 `Map<String, Map<String, ChatClient>>`

## 2. 对话模式

### 2.1 DIRECT（直接对话）
- 最简单的模式，直接将用户输入封装为 `UserMessage`
- 支持附带图片（多模态）

### 2.2 KNOWLEDGE_BASE（知识库 RAG）
- 流程：用户问题 → Redis 向量相似搜索 → 拼接上下文 → PromptTemplate 生成 Prompt
- 使用 `TokenTextSplitter` 分割文档（约 800 token/段）
- 批量向量化，每批 8 条（避免 API 限制）
- Prompt 模板包含 `{context}` 和 `{question}` 占位符

### 2.3 INTERNET_SEARCH（联网搜索）
- 流程：用户问题 → SearXNG 搜索 → 取 top-N 结果 → 按 score 排序 → 拼接上下文 → PromptTemplate
- SearXNG 配置：`https://searxng.140079.xyz/search`
- 默认获取 20 条搜索结果

## 3. 对话记忆

### 3.1 架构
- 基于 Spring AI `MessageWindowChatMemory`
- 最大保留 50 条消息
- 持久化：JDBC（`ChatMemoryRepository`）
- 通过 `MessageChatMemoryAdvisor` 注入 `ChatClient`

### 3.2 会话管理
- 每个对话通过 `chatId`（UUID）标识
- 会话元数据存储在 `conversations` 表
- 消息内容由 Spring AI 自动管理

## 5. 图片生成

### 5.1 配置

- API：DashScope Compatible Mode v1
- 分辨率：1024×1024

### 5.2 接口
```
GET /image/chat?prompt=描述文字
→ 返回图片 URL
```

## 6. SSE 推送

### 6.1 SSEServer
- 基于 `SseEmitter` 实现的 Server-Sent Events 服务
- 使用 `ConcurrentHashMap` 管理连接
- 支持消息类型：MESSAGE、ADD（流式追加）、FINISH、CUSTOM_EVENT、DONE
- 超时设置：0L（不超时）

> 注：SSE 功能已实现基础设施，但流式对话接口当前已被注释。

# 架构设计文档

## 1. 整体架构

系统采用经典的 **分层架构**，从上到下依次为：

```
┌─────────────────────────────────────────────────────┐
│                    客户端 (前端)                       │
└─────────────────────┬───────────────────────────────┘
                      │ HTTP / SSE
┌─────────────────────▼───────────────────────────────┐
│               拦截器层 (Security)                      │
│   JwtInterceptor → RoleInterceptor → @RoleRequired  │
└─────────────────────┬───────────────────────────────┘
                      │
┌─────────────────────▼───────────────────────────────┐
│              控制器层 (Controller)                     │
│  AuthController / ChatControl / CRUD Controllers    │
└─────────────────────┬───────────────────────────────┘
                      │
┌─────────────────────▼───────────────────────────────┐
│               服务层 (Service)                        │
│  ChatServiceImpl / AuthServiceImpl / CRUD Services  │
└───────┬─────────────┬───────────────┬───────────────┘
        │             │               │
┌───────▼─────┐ ┌─────▼─────┐ ┌──────▼──────┐
│ Mapper层    │ │ Repository │ │  外部服务     │
│ (MyBatis)   │ │  (Chat)    │ │  AI / OSS   │
└───────┬─────┘ └─────┬─────┘ └──────┬──────┘
        │             │               │
┌───────▼─────┐ ┌─────▼─────┐ ┌──────▼──────┐
│   MySQL     │ │   Redis   │ │ DashScope   │
│   数据库    │ │ VectorDB  │ │ ModelScope  │
│             │ │           │ │ SearXNG/OSS │
└─────────────┘ └───────────┘ └─────────────┘
```

## 2. 核心模块架构

### 2.1 多模型 AI 对话架构

```
ChatEntity (请求)
     │
     ▼
ChatControl ──→ ChatServiceImpl
                     │
                     ├── ChatClientFactory.getClient(modelName)  ← 懒加载 + ConcurrentHashMap 缓存
                     │        │
                     │        ├── ChatModelProperties (YAML 配置多平台模型)
                     │        └── OpenAiApi + OpenAiChatModel → ChatClient
                     │
                     ├── buildPromptByMode(chatEntity)
                     │        ├── DIRECT → new Prompt(UserMessage)
                     │        ├── KNOWLEDGE_BASE → DocumentService.doSearch → PromptTemplate
                     │        └── INTERNET_SEARCH → SearXngService.search → PromptTemplate
                     │
                     └── ChatClient.prompt()
                              .user(附加图片)
                              .advisors(ChatMemory 会话记忆)
                              .call().content()
```

**关键设计**：
- 使用 `ChatClientFactory` 实现模型的**懒加载**，首次请求时才创建 `ChatClient` 实例
- 同时保留了 `ChatModelConfig` 中的**预加载**方式（`Map<String, Map<String, ChatClient>>`），两种策略并存
- 对话记忆基于 `MessageWindowChatMemory`，限制 50 条消息窗口，通过 JDBC 持久化

### 2.2 安全认证架构

```
请求 ──→ JwtInterceptor ──→ RoleInterceptor ──→ Controller
          │                    │
          │ 校验 JWT Token     │ 检查 @RoleRequired 注解
          │ 解析 claims        │ 比对角色权限
          │ 注入 authUser      │
          │ 注入 authRole      │
          ▼                    ▼
       通过/拒绝 401        通过/拒绝 403
```

- **JWT 拦截器**：拦截 `/api/**` 路径，校验 `token` 请求头
- **角色拦截器**：检查 `@RoleRequired` 注解，基于 `X-Role` 请求头 或 JWT 中解析的角色
- **角色体系**：`ADMIN` > `TEACHER` > `STUDENT`

## 3. 配置架构

系统使用 YAML 配置驱动多平台 AI 模型：

```yaml
ai:
  platforms:
    - name: dashscope        # 平台名称
      api-key: sk-xxx        # API 密钥
      base-url: https://...  # 基础 URL
      options:
        - model: qwen3.5-flash   # 模型名
          temperature: 0.7       # 温度参数
          max-tokens: 1024       # 最大 token
```

通过 `ChatModelProperties` 绑定到 Java 对象，支持运行时动态切换模型。

## 4. 统一响应格式

所有 API 返回 `LeeResult<T>` 统一格式：

```json
{
  "code": 0,         // 0=成功, 非0=失败
  "message": "success",
  "data": { ... }
}
```
